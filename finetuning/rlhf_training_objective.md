## 🎯 The "Elevator Pitch"
> Since reward is non-differentiable, you can't backprop it directly. Instead, RLHF uses the **policy gradient trick**: weight each token's generation probability by how much better-than-average that token was (its **advantage**), then maximize that weighted probability — nudging the model to generate higher-rewarded tokens more often.

---

## 🧠 Core Mechanics

### 1. The Core Problem: Reward Is Not Differentiable

You have a model (the **policy** $\pi_\theta$) that generates token sequences. You have a reward $r$ on the full sequence. You want to update $\theta$ to maximize $r$.

**But you can't naively backprop $r$:**
- If reward comes from a verifier (e.g., code executor), there are no weights to backprop through — it's a Python `if` statement
- Even if reward comes from a reward model (which has weights), the LLM output is a **discrete sample** — sampling is a non-differentiable operation in the computation graph

**Q-learning doesn't transfer here either:** In classic Q-learning (which you know), you have a discrete, low-dimensional state/action space and a Bellman equation over them. In LLM RL, the action space is the entire vocabulary (~100K tokens), and the state is the entire conversation context. The Q-function becomes intractable to represent.

The solution: **Policy Gradient** — a family of algorithms that estimates the gradient of expected reward *without* differentiating through the reward function.

---

### 2. The Policy Gradient Intuition

The key identity (REINFORCE, Williams 1992):

$$\nabla_\theta \mathbb{E}[r] = \mathbb{E}\left[ r \cdot \nabla_\theta \log \pi_\theta(y \mid x) \right]$$

**Reading this in plain language:**  
"The gradient of expected reward equals the expected value of: reward × gradient of log-probability of that output."

**Why this works:** You sample an output $y$, compute reward $r(y)$, then nudge the log-probability of $y$ proportional to its reward. High-reward outputs become more likely. Low-reward outputs become less likely. Over many samples, this converges to a better policy.

**The LLM version:** Since outputs are token sequences, the log-probability of a full response is the sum of per-token log-probs:

$$\log \pi_\theta(y \mid x) = \sum_{t=1}^{T} \log \pi_\theta(y_t \mid x, y_{<t})$$

So the training objective becomes: weight each token's generation probability by the response-level reward, and maximize that.

---

### 3. Two-Phase Training: Why You Need a Reference Model

In practice, RLHF uses two phases per iteration:

**Phase 1 — Rollout collection (offline, fast):**
- The current model generates many responses to prompts
- The reward model / verifier scores all of them
- You collect a dataset of $(x, y, r)$ trajectories
- This is just inference — large batches, no gradients, very fast

**Phase 2 — Policy update (online, expensive):**
- You train on the collected trajectories
- The model weights change with every mini-batch
- But the trajectories were generated by the *old* model (from Phase 1)

**The mismatch problem:** After a few gradient steps, the current policy $\pi_\theta$ has diverged from the policy that generated the rollouts. Using $\pi_\theta(y_t | x)$ directly in the loss creates an inconsistency — you're weighting new probabilities against old data.

**The fix: Importance Sampling Ratio**

Instead of using current probability directly, use the **ratio** of current policy to the reference policy that generated the data:

$$\rho_t = \frac{\pi_\theta(y_t \mid x, y_{<t})}{\pi_{\text{ref}}(y_t \mid x, y_{<t})}$$

- $\rho_t > 1$: current model is *more* likely to produce this token than the reference
- $\rho_t < 1$: current model is *less* likely
- $\rho_t = 1$: no change from reference

This ratio corrects for the distribution mismatch between the data-generating policy and the training policy. It's the core tool of **off-policy** RL.

---

### 4. The Advantage: Centering Rewards Around Zero

Using raw reward $r$ directly causes a training problem: if all rewards are positive (e.g., all between 0 and 1), the model tries to increase the probability of *every* token, just some more than others. Learning is slow because the signal is all in the same direction.

**The fix: subtract a baseline $b$** to get the **advantage** $A$:

$$A = r - b$$

The baseline $b$ estimates the *expected* reward — how well the model was expected to do on this token/sequence. The advantage measures whether the output *exceeded or fell short of expectations*:

- $A > 0$: this response was better than average → increase its probability
- $A < 0$: this response was worse than average → decrease its probability
- $A = 0$: exactly average → no update

**Why this matters:** With a good baseline, rewards are centered around zero — a mix of positives and negatives — giving much clearer gradient direction and dramatically faster learning. (Empirically shown to speed learning 3–5×.)

In RL literature: $b$ is the **value function** $V(s)$, and $A = r - V(s)$ is the **advantage function**.

---

### 5. The KL Divergence Penalty: The Safety Tether

Without any constraint, the policy optimizer will exploit the reward model — finding adversarial outputs that score high but are incoherent. The solution: add a **KL divergence penalty** to the reward that punishes the current policy for drifting too far from the reference (SFT) model:

$$r_{\text{effective}} = r - \beta \cdot D_{KL}(\pi_\theta \| \pi_{\text{ref}})$$

$$D_{KL}(\pi_\theta \| \pi_{\text{ref}}) = \log \frac{\pi_\theta(y_t \mid x)}{\pi_{\text{ref}}(y_t \mid x)}$$

**Intuition:** The SFT model is a strong prior over coherent, grammatical, factual text — trained on trillions of tokens. By constraining the policy to stay "close" to the SFT model (in KL sense), you inherit its linguistic competence while only moving in reward-maximizing directions.

**The Pareto tradeoff:**  
There is a fundamental Pareto frontier between reward maximization and KL minimization — you cannot simultaneously do both. The coefficient $\beta$ controls where you sit on this frontier:
- **High $\beta$** → conservative updates; model stays close to SFT; less reward hacking but slower improvement
- **Low $\beta$** → aggressive updates; model can drift far; better peak performance but vulnerable to reward hacking

**Typical values:** $\beta \approx 0.1$–$0.2$ for 7B–13B models. Adaptive controllers that adjust $\beta$ dynamically are common in production.

---

### 6. The Full RLHF Training Objective (Basic Form)

Putting it all together, the objective to **maximize** at each training step is:

$$\mathcal{J}(\theta) = \mathbb{E}_{(x,y) \sim \pi_{\text{ref}}} \left[ \sum_t \rho_t \cdot A_t \right] - \beta \cdot D_{KL}(\pi_\theta \| \pi_{\text{ref}})$$

Where:
- $\rho_t = \pi_\theta(y_t) / \pi_{\text{ref}}(y_t)$ — importance sampling ratio
- $A_t = r - b_t$ — advantage (reward minus baseline)
- $\beta \cdot D_{KL}$ — KL penalty keeping model grounded

**Number of models in memory:**

| Model | Role | Trainable? |
|---|---|---|
| **Policy LLM** ($\pi_\theta$) | The model you're improving | ✅ Yes (full grads) |
| **Reference LLM** ($\pi_{\text{ref}}$) | Frozen SFT checkpoint | ❌ Frozen |
| **Reward Model** | Scores rollouts | ❌ Frozen during RL |
| **Value/Baseline Model** | Estimates expected reward per token | ✅ Yes (PPO only) |

This is why RL training is ~4× more memory-intensive than SFT.

## ⚠️ Edge Cases & Constraints

**Sparse reward problem:** The reward is given at the *sequence level* (after the full response), but the model must learn which specific *tokens* caused the high/low reward. This is the credit assignment problem. The advantage baseline helps (especially per-token baselines like GAE in PPO), but it remains challenging.

**KL collapse:** If $\beta$ is too high or training runs too long, the KL penalty dominates and the policy stops improving — it's essentially frozen near the SFT model. Monitor KL divergence during training; it should grow gradually.

**Off-policy staleness:** The longer Phase 2 training runs on Phase 1 data before refreshing rollouts, the more stale the importance weights become. Clipping the ratio (PPO's core trick) partially compensates, but rollout refresh frequency is a critical hyperparameter.

**DPO as an alternative:** Direct Preference Optimization (Rafailov et al., 2023) bypasses the RL loop entirely. It derives a closed-form loss directly from preference pairs, showing that the RLHF optimal policy has an analytical solution. No reward model, no RL loop, no value function needed — just supervised learning on preference pairs. Trade-off: DPO is more stable but cannot explore beyond the offline training distribution.

## 💻 Logical Code Snippet (Python)

```python
import torch
import torch.nn.functional as F

# ─────────────────────────────────────────────────────────────
# The core RLHF training objective — conceptual implementation
# ─────────────────────────────────────────────────────────────

def compute_log_probs(model, input_ids, response_ids):
    """Get log P(token_t | context) for each token in the response."""
    logits = model(input_ids).logits          # (batch, seq_len, vocab)
    # Align: logits at position t predict token at t+1
    log_probs = F.log_softmax(logits[:, :-1, :], dim=-1)
    # Gather log-prob of the actual token chosen at each step
    token_log_probs = log_probs.gather(
        dim=-1,
        index=response_ids[:, 1:].unsqueeze(-1)
    ).squeeze(-1)                              # (batch, response_len)
    return token_log_probs


def compute_kl_penalty(policy_log_probs, ref_log_probs):
    """
    Per-token KL: log(π_θ / π_ref) = log π_θ - log π_ref
    Sum over response tokens, mean over batch.
    """
    return (policy_log_probs - ref_log_probs).sum(dim=-1).mean()


def rlhf_loss(
    policy_model,
    ref_model,
    input_ids,
    response_ids,
    advantages,      # (batch, response_len) — centered rewards per token
    beta: float = 0.1,
):
    """
    Basic RLHF policy gradient loss with KL penalty.
    Maximize: Σ_t [ ρ_t · A_t ] - β · KL(π_θ || π_ref)
    """
    # Current policy log-probs
    policy_log_probs = compute_log_probs(policy_model, input_ids, response_ids)

    # Reference model log-probs (frozen — detach from graph)
    with torch.no_grad():
        ref_log_probs = compute_log_probs(ref_model, input_ids, response_ids)

    # Importance sampling ratio ρ = π_θ / π_ref (in log space: subtract log-probs)
    log_ratio = policy_log_probs - ref_log_probs    # (batch, response_len)
    ratio     = log_ratio.exp()                     # (batch, response_len)

    # Policy gradient term: weight token prob by advantage
    pg_loss = -(ratio * advantages).sum(dim=-1).mean()

    # KL penalty: punish divergence from reference
    kl_penalty = (log_ratio).sum(dim=-1).mean()     # E[log ρ] ≈ KL

    total_loss = pg_loss + beta * kl_penalty         # minimize this
    return total_loss


# ─────────────────────────────────────────────────────────────
# Advantage computation — reward minus baseline
# ─────────────────────────────────────────────────────────────

def compute_advantage_simple(rewards, value_estimates):
    """
    rewards:         (batch,) — sequence-level scalar reward
    value_estimates: (batch,) — baseline (expected reward from value model)
    Returns: advantages (batch,) — centered around zero
    """
    advantages = rewards - value_estimates
    # Normalize for more stable gradients
    advantages = (advantages - advantages.mean()) / (advantages.std() + 1e-8)
    return advantages
```

## 🔬 Frontier Research & Papers

| Topic | Key Insight | Reference |
|---|---|---|
| **InstructGPT (RLHF baseline)** | First paper establishing the full 3-stage RLHF pipeline (SFT → RM → PPO) for instruction following; formalized the KL-penalized objective | Ouyang et al., NeurIPS 2022 |
| **REINFORCE (Williams 1992)** | The foundational policy gradient theorem — reward × log-prob gradient — that all modern LLM RL builds on | Williams, Machine Learning 1992 |
| **DPO (Direct Preference Optimization)** | Derives a closed-form loss from the RLHF objective — shows the optimal policy can be expressed analytically from preference pairs, bypassing the entire RL loop. Now the default for alignment on limited compute | Rafailov et al., NeurIPS 2023 |
| **KTO (Kahneman-Tversky Optimization)** | DPO requires *pairwise* data (chosen + rejected). KTO works with *unpaired* signals (thumbs up / thumbs down on individual responses), inspired by prospect theory's asymmetric treatment of gains vs. losses | Ethayarajh et al., 2024 |
| **N Implementation Details of RLHF with PPO** | Documents 11 critical, underdocumented engineering details (reward normalization, value function warmup, response truncation, etc.) without which PPO training fails silently | Huang et al., 2023 |
| **KL Divergence in RLHF** | Formalizes the Pareto frontier between reward and KL; shows different $\beta$ values trace fundamentally different learning trajectories; argues KL is a *structural* constraint on what RLHF can achieve | Brenndoerfer, 2025 |
| **DAPO** | Removes the KL penalty entirely and replaces it with clip-higher + entropy bonus; shows KL penalty can harm training on complex reasoning tasks | Yu et al., 2025 |
